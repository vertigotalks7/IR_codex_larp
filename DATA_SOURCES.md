The metro catalog contains 21 source-linked system records; ten have local route geometry, and eleven are visibly marked as pending local geometry. The browser bundle (`public/data/routes.json`) contains 626 geometry features across ten active map selectors: Delhi 305, Bengaluru 3, Chennai 76, Hyderabad 3, Kochi 55, Mumbai 90, Pune 38, Noida 31, Gurugram 18, and Navi Mumbai 7. These comprise 620 individual OSM track ways and six GTFS shapes; a geometry-feature count is not a station count or a number of distinct services. The OSM query base timestamp is 11 October 2026. The only dated GTFS source in the local inputs is Hyderabad (3 July 2026); the Bengaluru and Chennai feed snapshot dates are not recorded. HMRL asks for the attribution “Contains data provided by Hyderabad Metro Rail Ltd.” and reserves its rights in the data; see [HMRL open-data terms](https://hmrl.co.in/open-data/). Metro geometry is loaded from the local bundle and does not depend on a runtime Overpass request. The map click inspector links each OSM way or identifies a GTFS shape. These OSM ways are community-mapped physical infrastructure, not operator-certified complete service paths; OSM tagging can be incomplete. Chennai ways without a line tag use a neutral color rather than being assigned to a named line. Mumbai's physical OSM tags group some Line 2A/2B infrastructure under the generic label “Line 2”; the dashboard reports the operator's corridor roster separately. The old hand-authored station-connector route arrays have been removed. The History page provides source-linked events and coverage infographics; it does not animate or reconstruct historical track geometry.

Station coordinates are stored separately from route geometry. The combined point bundles contain 121 unique HOTOSM/OSM source objects: Kochi 25 records/25 names, Mumbai 66/65, and Pune 30/29. Point coordinates are copied from the 10 May 2026 snapshot; Vyttila and ten Mumbai Line 1 markers are calculated as centroids of mapped station-footprint polygons, with source IDs and derivation recorded. Kochi's 25 named-stop roster is mapped, but its homepage separately says 26. Mumbai has partial coverage on Lines 2A, 2B, and 3; Pune's 29 distinct names align with the current 29-operational figure, with two Civil Court objects retained and a Kasba Peth/Budhwar Peth label discrepancy. These are map-point records, not an all-network count. The History page presents operator figures separately from map records and links every listed point to its OSM object.

## Railway administrative history directory

The History selector lists 18 railway organizations: 17 operating zones with 69 divisions, plus Metro Railway, Kolkata (no operating divisions in the roster). The base membership and creation-year records come from the [Railway Board roster](https://indianrailways.gov.in/railwayboard/uploads/directorate/eff_res/Re_organization/List%20of%20Zones%20%26%20Divisions061123.pdf) (6 November 2023), revised for South Coast Railway’s 1 June 2026 operational start and the Visakhapatnam/Rayagada division reorganization using [Ministry of Railways records](https://www.pib.gov.in/PressReleasePage.aspx?PRID=2256199&lang=1&reg=20) and the [Cabinet divisional decision](https://www.pib.gov.in/PressReleaseIframePage.aspx?PRID=2100853&lang=2&reg=48). The current Railway Board directory is [here](https://dir.railnet.gov.in/) (updated through July 2026). This is an administrative selector, not a complete division GIS/service-history dataset. Junction and corridor infographics remain limited to records currently indexed in `src/data/nationalRailways.ts` and disclose that sample size.

Each dated card links directly to its supporting record in the UI. “Location” is a geographic lens supported by the linked railway map/profile, not a digital division boundary; the plotted dots are only the project’s sparse local junction sample. Bilaspur (SECR) is the sole division explicitly marked “research pending”: the official roster and divisional map provide administrative context, but the research did not locate enough division-specific primary historical material to write a distinct, well-supported chronology.

## Live train-running information

- The map currently renders static, locally bundled GIS/GTFS geometry; it does not show live train positions, live delays, or a real-time vehicle feed.
- [CRIS describes NTES](https://www.cris.org.in/loadpage?page=proNTES) as providing near-real-time passenger train-running information, including queried running status and station ETA/ETD. The atlas header links visitors to the [official NTES passenger enquiry](https://enquiry.indianrail.gov.in/mntes/).
- CRIS describes operational feeds between its [Control Office Application and NTES](https://www.cris.org.in/loadpage?page=proCOA), and its [RTIS](https://www.cris.org.in/loadpage?page=proRTIS) uses onboard satellite equipment to send movement updates into railway systems. Those descriptions do not constitute a documented public browser API or a reuse license for this project. No public API contract/GTFS-Realtime feed was identified during this research.
- Therefore the project does not scrape NTES pages, undocumented endpoints, authenticated systems, or use a simulated marker as if it were live. A future live layer requires an authorized CRIS/API agreement and documented schema, access limits, attribution, privacy and caching terms. The [Railway Board timetable dataset](https://www.data.gov.in/catalog/indian-railways-train-time-table) is a historical/static timetable dataset, not a live substitute.

## Indian Railways national track layer

- Generated route asset: `public/data/railway-routes.json` (2,390 grouped features); junction layers are in `public/data/railway-major-junctions.json` and `public/data/railway-junctions.json`.
- Local build input: `Railway_Network_.geojson` (about 83.6 MB). The raw input is excluded from Git. Its filename and properties do not establish an upstream provider or snapshot date, and this repository does not contain a source URL or a reliable chain of custody. Therefore the map and UI call it a project railway-GIS snapshot, not an official or current Indian Railways dataset.
- `scripts/build-railway-network.mjs` simplifies and groups input geometry and derives junction points. Its output features are physical track sections, not scheduled train paths. It must not be treated as proof of service, operational status, or current speed.
- Rebuild with `npm run data:build:rail` after obtaining the exact source file and recording its provider, license, publication date, and checksum. Without that provenance, keep the committed generated asset as-is and do not claim the pipeline is reproducible from this repository alone.

## City rail track context (shown under “Suburban Rail”)

- Source: [HOTOSM India Railways dataset on HDX](https://data.humdata.org/dataset/hotosm_ind_railways), extracted from OpenStreetMap; license reported in the snapshot README as ODbL.
- Snapshot date: 10 May 2026, as recorded in `data/source/hotosm/README.txt`.
- Geometry: physical `railway=rail` ways and `railway=station` points, clipped to twelve city-focus bounds: Mumbai, Kolkata, Chennai, Delhi NCR, Hyderabad, Pune, Bengaluru, Ahmedabad, Jaipur, Lucknow, Nagpur, and Bhopal. The builder preserves the source line paths and clips them at city boundaries; it does not infer routes between stations.
- Important limitation: these are mapped tracks in urban extents, not operator-verified suburban train services. The data does not distinguish passenger, commuter, or freight use and does not support the previous ridership or route-km figures. The interface labels this distinction.
- The raw 91.9 MB source is excluded from Git. To rebuild, place the matching `railways.geojson` and source `README.txt` under `data/source/hotosm/`, then run `npm run data:build:suburban`. The app fetches only the selected city's bundle; selecting all areas fetches all twelve.
- “Suburban Rail” remains a UI layer name for city rail context. These are not verified commuter-service routes, and a focus area does not imply that a dedicated suburban rail system operates there. K-RIDE's [project page](https://kride.in/sub-urban-rail-project/) and [current tender listings](https://kride.in/tender/) document the separate Bengaluru Suburban Rail Project (BSRP), which is still under construction. A 2026 Corridor 4 package KMZ was reviewed, but it contains thousands of unlabeled engineering drawing shapes rather than an identifiable corridor centerline; it is not used as service geometry. BSRP is not drawn as commissioned service.

## NHSRCL / high-speed rail

- Reference: [NHSRCL project overview](https://nhsrcl.in/index.php/en/project/project-overview) and [official technical details page](https://www.nhsrcl.in/en/project/technical_details). The technical-details page, last updated 27 May 2026, lists an MAHSR alignment KMZ download.

## Map base and runtime behavior

- Basemap tiles: [OpenStreetMap](https://www.openstreetmap.org/copyright), fetched at runtime. Tile availability depends on network access and OSM tile usage policy.
- Route data is bundled as static GeoJSON. There is no application backend or live tracking API. `data/routes.sqlite` is a local build artifact; the browser reads the generated GeoJSON export.
- The map status reflects loaded data. Failed/missing geometry leaves the route layer empty; runtime connector fallbacks are not used.
